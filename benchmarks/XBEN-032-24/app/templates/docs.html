WPS Execute Request Format

The WPS Execute operation is used to run a specific process with provided inputs. Send XML requests via HTTP POST to /wps.

Request Structure

<?xml version="1.0" encoding="UTF-8"?>
<wps:Execute xmlns:wps="http://www.opengis.net/wps/1.0.0"
             xmlns:ows="http://www.opengis.net/ows/1.1"
             service="WPS" version="1.0.0">
    <ows:Identifier>process_identifier</ows:Identifier>
    <wps:DataInputs>
        <wps:Input>
            <ows:Identifier>input_name</ows:Identifier>
            <wps:Data>
                <wps:LiteralData>input_value</wps:LiteralData>
            </wps:Data>
        </wps:Input>
    </wps:DataInputs>
</wps:Execute>

Example: Buffer Operation

curl -X POST http://localhost/wps \
  -H "Content-Type: application/xml" \
  -d '<wps:Execute xmlns:wps="http://www.opengis.net/wps/1.0.0"
             xmlns:ows="http://www.opengis.net/ows/1.1"
             service="WPS" version="1.0.0">
    <ows:Identifier>geo:buffer</ows:Identifier>
    <wps:DataInputs>
        <wps:Input>
            <ows:Identifier>geometry</ows:Identifier>
            <wps:Data>
                <wps:LiteralData>POINT(10 20)</wps:LiteralData>
            </wps:Data>
        </wps:Input>
    </wps:DataInputs>
</wps:Execute>'
Note: The WPS service uses the lxml XML parser for processing requests. Ensure your XML is well-formed before submission.

Response Format

Successful Execute requests return an ExecuteResponse document containing:

  • Process identifier and status
  • Echoed input values for verification
  • Processing results and job ID

Error Handling

Errors return OWS ExceptionReport documents with appropriate exception codes:

  • InvalidParameterValue - Invalid parameter provided
  • MissingParameterValue - Required parameter missing
  • OperationNotSupported - Unsupported operation
  • NoApplicableCode - General processing error
